# 简历规则（表述 · 证据 · 排版 · 沟通）

> 操作步骤 → [workflows/resume.md](../workflows/resume.md)。智能默认 → [ROUTER.md](../ROUTER.md)。  
> 主张账本 → [claim-evidence-ledger.md](../references/claim-evidence-ledger.md)。

## 表述

1. 删内部指代；缩写用 `external_plain_zh` 或 中文（English）
2. **负责 + 可核验结果**；并列 bullet 结构对齐
3. 技能从 `tools` 聚合，**无证据不写**
4. 包装 = 把事实翻成招聘方好懂、可追问的话；**不**虚构头衔、公司、项目、技术栈或数据

### 经历改写骨架

项目整体讲清：**问题或需求 → 方法选择与研究/工程判断 → 个人贡献 → 具体发现或交付 → 当前岗位相关价值**。信息可分布于多条 bullet，按读者理解顺序组织，无需每条塞满所有要素或固定两条。

- 研究经历体现如何提出可检验问题、设计测量与对照、选择方法、解释发现，以及将学科专长转化为目标岗位可用的方法；工程经历体现约束、方案、实现和交付。内容重心由当前 JD 决定。
- 加厚叙事时补入关键方法、判断、发现及其联系。成果位置应有实际结果，避免用内部核验动作或重复的抽象价值句代替。
- 主动说明结果对目标岗位的具体意义。用“发现/交付”陈述已完成成果，用“为……提供方法/依据”表达有证据支持的应用价值；研究启示不能写成已完成工程应用。
- 通过准确角色、动词、任务和输入模态表达范围，保留影响指标解释的验证条件。个人边界存于经历档案/面试准备，正文不追加自我辩护式说明。
- 每条项目 bullet 默认采用 **加粗短标题＋连贯正文**。短标题概括本条实质贡献，各项目格式一致；正文自然衔接，避免机械重复起手句。用户明确指定其他格式时遵从。

### 强动词门禁

「主导 / 负责人 / Owner / 0→1」仅当能说明决策、交付与结果；否则改「负责模块 / 参与 / 协作」。非本人负责写清「团队」或标待确认。

### 量化门禁

每条产业 bullet **尽量含**以下之一：数字 / 比例 / 样本量 N / 时效。
无数字则用定性可核验结果（交付物、venue、开源链接），并在选材表标 `claimed`。不编百分比/用户量/延迟/排名。
**定稿 bullet 只收已确认量化**；`claimed` / 待确认强数字改定性表述或先问清再写。

### 主张审计（Mode · jd 必做；pitch 有强主张时做）

强主张列表：原始说法 | 建议写法 | 事实证据 | 个人边界 | 风险/待确认。
跨岗多版本或冲突多时，可写入工作区账本（见 claim-evidence-ledger）；**成稿只消费已确认主张**。

### 产业 vs 学术

| | 产业 | 学术 |
|--|------|------|
| 语气 | 交付、指标 | 可保留方法名、在投 |
| 弱项 | 压入「其他」或删 | 可留报告/服务 |

### 禁止上简历

`internal` 术语、未裁决冲突数字、`constraints.false_if_claimed`、**`role_and_boundary` 原文**（边界只存经历档案/面试准备，**禁止**写进 bullet 括号说明）。

### 技能证据绑定

skills 行每个工具/能力须至少对应一条 engagement 的 `tools` 或 bullet 证据；无证据不写。按 JD 精选面试官可识别的工具、模型方法与测评技术，必要时分少量类别；压缩泛化能力词及正文的重复概括，不为覆盖关键词堆砌技能。

## 披露 · ATS

- `essential`：**保留**工具名/专名（可括注中文），兼顾 HR 与关键词
- `plain_only`：只用 `external_plain_zh`
- JD 硬技能与经历档案一致时，可 mirror 到 skills 行（不编造）；**每个硬词须能指回**某条 engagement `tools` 或已选 bullet

### ATS 纯文本

**投递版优先**从 HTML 导出（与 HR 看到的 PDF 一致）：

```powershell
python scripts/export_plain.py --from-html resumes/industry_<slug>.html --in ssot.json --out resumes/industry_<slug>.txt
```

通用版/无 HTML 时：

```powershell
python scripts/export_plain.py --in ssot.json --out resumes/industry_base.txt --track industry
```

`export_plain` 会应用 `term_registry`（`internal` 删除、`plain_only` 替换）。

网申要 Word：txt → Word 另存 docx。

## 排版

- HTML 源；内联 CSS；`body` 打印 `width: 100%`；**不要**叠 `max-width: 210mm`
- 模板：[resume-industry.html](../../templates/resume-industry.html)（含**工作经历**区块）
- 历史定稿按工作流选择；无合适历史稿时对照 [example-resume.html](../../fixtures/example-resume.html)（公开虚构样例）。模板与样例是可调整的骨架，选材和叙事服从当前 JD。
- 默认采用单栏、细分隔线、日期右对齐的清晰布局；以下叙事、排版和验收标准直接适用于每次制作，用户本次明确要求可调整。私人简历及具体路径留在工作区，包内不嵌入个人经历或绝对路径。

### 页数

| 场景 | 目标 |
|------|------|
| 实习 / 应届 / JD 投递 | **1 页** |
| 博士 / 3 年+ | **1–2 页** |
| 储备版 | 可略超 |

按用途判定：博士参加校招/JD 投递默认仍为一页，学术或完整资历版可用一至两页；本次要求优先。

一页同时要求内容充实与阅读舒适。过密时先删重复空泛句、压缩低相关内容及辅助栏目，保留主项目逻辑；再修整短标题、短尾行、行距和项目/栏目间距，最后微调字号。空间富余时补足有价值的相关叙事或适当增加间隔，不靠无关内容填满。实际 PDF 检查字号、密度、层级、日期对齐、换行、页底留白及溢出；页数检查不能代替视觉检查。

### 模块顺序（产业）

默认：教育 → **工作经历**（有则写）→ 项目 → 代表作 → 技能 → 其他。按 JD、资历和用户本次要求调整，空栏目省略；相关研究统一为项目，不按含义重叠的名称重复分栏。

页眉保留应聘意向、身份与联系方式，避免额外能力口号及岗位编号独占行。多意向共用稿分别写明岗位，选材覆盖共同能力和各自关键要求。

代表作精选与岗位相关的成果，统一作者、年份、题名、刊物、作者身份与链接格式；突出本人姓名及一作/共一/封面等重要信息。发表状态写在条目内，不另占分组标题；具体顺序按岗位相关性与成果分量决定。

### 项目 bullet 骨架（产业）

项目标题突出主题，机构/范围与角色为辅助信息，日期右对齐。最能证明本次岗位核心能力的项目优先展开，其余压缩辅助，不按机构名气或旧稿顺序自动前置。

每条短标题后用自然语句展开，逻辑见「经历改写骨架」。加粗集中于项目名、短标题、核心贡献、主结果及重要成果；辅助数字保持常规字重，避免整句或连续数字全部加粗。

### 照片

优先遵从用户本次要求及工作区 `config.json` 的照片配置；未指定时默认**无**（模板已注释），CN 岗需要时取消注释。

## HR 自检

jd 版首次交付前完成内容与视觉两轮验收，发现问题先修正再交付：

1. **岗位主线**：选材、首个项目及篇幅服务当前 JD；关键实习/工作可见；参考版本借鉴点明确，最新用户纠正已落实。
2. **项目叙事**：核心项目呈现问题、方法判断、本人贡献和具体发现/交付；价值与结果相连，短标题格式一致，无空泛填充或内部操作占据成果位置。
3. **证据与技术**：数字对应任务、模态和必要条件；角色与成果状态准确；强主张已核查，无待确认强数字和 internal 术语。技能精选且逐项有据，不以数量要求补造关键词。
4. **信息与结构**：联系方式完整，栏目与代表作格式符合本技能规则和用户本次要求；页眉简洁、层级清楚。
5. **实际页面**：页数符合用途，已查看最终 PDF 的字号、密度、换行、对齐、间距及留白，阅读舒适且无溢出。
6. **导出一致**：PDF 与网申文本来自最终 HTML；链接可用，原定稿保留。交付短报只说明参照、岗位取舍与验收结果。

## 沟通文案（不进经历档案）

- **开场短版**约 80—160 字：身份与方向 → 一个真实成果 → 邀请继续聊（Boss/微信）
- **自我介绍**稍完整但仍短；事实只来自经历档案
- Networking：50 / 150 / 300 字
- 求职信 `cover_letter_<slug>.md`：Why company / Why role / Why me，禁止虚构

岗位定位可给 1—3 个（稳妥 / 进取）；进取须写清待补证据。

## 禁止

虚构经历；因 JD 回写经历档案（除非用户补充新事实）；把包装话术当事实写入 `ssot.json`
