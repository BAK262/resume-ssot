# Offer comparison and negotiation

本流程用于对比 Offer、拆解薪酬、谈薪准备、读取招聘方方案和同步手动修改。对用户称“Offer 对比看板”。

入职日期记录为 YYYY-MM-DD；历史 YYYY-MM 保留已知月份并提示补具体日期，不能补造 1 日。月度测算从日期提取月份，首月工资按已确认系数计算。

默认是一张完整对比表，业务维度收敛为岗位成长、薪酬福利、工作生活、录用签约四组；22 行输入（含两行测算资料入口与自定义项），每项只出现一次。对比表完整展开，随页面滚动。相近的文字字段在同一格编辑，工资和税务参数通过表内入口集中填写。单元格只编辑实际内容；待补充是按空值筛选，不要求逐项填写来源、确认程度、日期、备注。表内自动汇总，表外薪酬分析共用同一份数据，提供收入构成、逐月现金流、多机会同年度对比图；主要结果只保留预计到账、汇算后现金、公积金账户新增三项，首年、扣款和逐月数字按需展开。

## Artifacts and boundaries

- 私有记录唯一文件：`offers/offer-comparison.html` 的 `offer-data` JSON；浏览器 localStorage 是尚待同步的编辑副本。
- 通用模板 `templates/offer-board/`、脚本 `scripts/render_offer_board.js` 与虚构 fixtures 可公开。真实方案、聊天截图、联系人和报酬只在用户工作区。
- 进度表仍管理招聘进度。比较表管理条件和决策。经历档案不存投递／薪资；不把意向通知升格为正式报价。
- 读取求职画像，让研究主责、技术贡献、成长、城市与毕业时间成为比较依据。不要默认薪酬权重或总分；用户自行选择。

## Intent-based linkage

1. 每次更新投递到 `Offer` 或维护对比表时，读取进度表确切 immutable ID，查 `trackerId` 是否已存在；同公司不同岗位分别核实。已有记录原位更新。
2. 对进入 Offer 阶段的岗位建立条件记录，即使只是录用意向。阶段写清“意向通知／口头报价／书面方案／正式通知”等实际证据；缺失报酬留 null。
3. 手动新增允许没有 trackerId；后续核实同岗位再关联。不能因同公司就合并。
4. 拒绝、撤回或流程结束时保留比较和谈判历史，按用户意图归档。只有明确进度事实才回写进度表。更新投递状态保持原流程约定。
5. 联动由 Agent 按意图执行，不增加后台爬取、状态轮询或 HTML 间脚本同步。

### Proactive evidence updates

- 岗位首次进入 Offer 阶段（含录用意向），或首次建立该岗对比记录时，主动回查该岗已有面试复盘、机器转写、招聘沟通及其他相关材料，按当前可见比较项提取已知信息并写入对比表。
- 对已进入 Offer 阶段的机会，用户补充消息、口述、截图、文件、复盘或员工反馈时，主动提取影响岗位成长、薪酬福利、工作生活或录用签约的增量信息，当轮更新对应单元格，无需等待用户再次说“更新对比表”。用户明确仅讨论或暂不落盘时，遵循其范围。
- 已有材料先查复盘定位，再按需核对转写。记录业务方说明、员工转述及尚未确定的条件，保留来源与时间；新信息与旧材料冲突时标明分歧，避免把个人判断升级为正式条件。
- 准备向招聘方或业务负责人追问前，先用已有材料补齐可回答的比较项，只对仍影响选择的缺口提问。用户要求更新时，当轮完成文件写回和核验，并说明更新了哪些可见比较项。写回遵循下方合并及字段归属规则。

## Materials to fields

1. 读取用户提供的原始文字、PDF、截图、邮件或转写。可辨认部分才填；看不清、含糊或互相冲突的条款明确标出。
2. 每个字段维护实际 value；“年包”“几薪”的原话与含义写入对应业务条款。无需逐项采集元信息。原始材料按 Offer 整体留在私有工作区供核对。旧版 source/status/date/note 保持兼容存储，普通手动编辑只更新 value，不删除已有证据。
3. 现金拆成固定、浮动、一次性；股权和报销单列。每项记录单次税前金额、频次、发放年月、期间、试用折扣、税务处理和兑现条件。免税适用依据仍属于必要计算条件。额外薪月与年终奖避免重算。金额未知=null，确认为无=0。
4. 年度项目按实际发放月计入；首年折算、薪资调整、月中入职按已确认系数或分期间／一次性金额录入。未明确奖金归属与发放条件，不声称保底。
5. 缴费按险种独立录入月额或基数／个人单位比例／上下限／附加额／取整／起止月／来源。同一名称的期间不可重叠。确认缴费起月，尤其首次就业公积金；参保地不必等于办公地。核实可税前扣除范围，单位缴费不当作现金。
6. 政策每次查实际城市官方来源及生效期间。未来政策未知可明确写规则延用假设；不填成“已核实”。经验帖只生成问题，不能代替税务规则。
7. 确认是否大陆税收居民、首次就业预扣资格、其他综合所得收入额与预扣、全年专项附加扣除、奖金优惠是否已经使用。不能把未知背景填 0。当前计算器只支持居民工资和合格全年一次性奖金；股权复杂计税等保持单列，查证后处理。

## Editing and safe synchronization

- 用 `core.js` 的 `newRecord/cell/validate` 创建数据。字段定义就在 `groups`；金额不直接改计算结果。
- AI 写文件前合并用户导出。导出包含 baseline，脚本三方合并，独立修改保留；同字段冲突停止写入，展示两种值并依据证据解决。不能用时间较新静默覆盖。
- `node scripts/render_offer_board.js --input <existing.html> --merge <export.json> --out <existing.html>`。
- 新建或已经核实合并的 JSON：`node scripts/render_offer_board.js --input <private.json> --out <workspace>/offers/offer-comparison.html`。临时 JSON 用后清理；不要保留第二份长期主数据。
- 后续无数据变化的模板刷新：input 和 out 同一个 HTML。始终保持 boardId、record id 和 trackerId。
- 文件更新后浏览器会按基线合并本机修改；同字段差异显示选择框。手动编辑不会直接写磁盘，跨设备前导出并同步文件。用户已提供编辑导出才视为拿到该浏览器最新内容。
- 修改真实报价前存 `versions` 快照（label、date、cells）。假设只存试算，只有用户确认已获得该方案才转真实记录；保留政策假设标签和来源，不能把全部假设标为 HR 书面确认。
- 新增导航只改导航；证明 tracker initialRecords 未变化。没有真实 Offer 不制造示例机会进入私有表。

## Calculation and explanation

税前固定／目标现金、逐月预扣后到账、年度汇算后现金、前12个月、个人缴费、公积金账户增加分别解释。年中入职的年度÷12不是正常工作月工资；用逐月表看普通月份。目标收入假定所填浮动金额实际兑现，不是保证收益。

年终奖单独计税政策仅核实至 2027-12；跨年奖金按支付年份核实资格。同一年度多次选择单独计税或已使用资格时不给有效结果。累计预扣不退款，汇算退款单列；工资预扣不把其他单位预扣简单合并成同一雇主税表。全年汇算含其他收入时结果不能归因于本 Offer 独立税负。

关键资料不全时税后显示待确认，税前仅显示已录小计。政策期间过期需补齐缴费参数；工资规则未来延用明确显示试算。每项输出可追溯原始输入。低于零的净现金也应显示并说明，而非悄悄截为零。

## Negotiation and acceptance

按 HR、业务负责人、员工、本人整理待问项。先核实完整口径，再对比目标和底线；可以拟索取文字方案、争取思考时间、讨论固定薪／职级／签字费／城市等的自然消息。真实备选只能按实际进展描述。未经明确授权不发送、不接受 Offer、不签三方。

每轮记录对方原话、日期、变化、未解决项、回复期限。接 Offer 前复核签约主体、岗位地点、入职条件、试用与转正、奖金与返还、竞业与知识产权；事实、个人偏好和建议分开。

## Verification

`node tests/test_offer_board.js` 验证计算、合并、注入和渲染边界；`node tests/test_offer_app.js` 验证页面逻辑与存储合并；`python tests/test_scripts.py` 验证现有功能。浏览器检查总览、横向对比、手动编辑、假设测算、导出导入、冲突及刷新保留；虚构记录用于测试。真实板确认无虚构金额、不会污染进度表。

## Input ownership and simplification

- 收入金额、频次和发放／返还条件归收入项目；工资、额外薪月、年终奖、现金补贴和一次性收入各录一次。总额是计算结果；原始报价材料由 AI 按需核对。
- 缴费按月额或基数比例二选一，界面只显示该方式所需参数。零试用月自动使用全薪系数；周期收入缺少起月时沿用入职月。不得从含糊文字推断现金金额或确认资格。
- 月专项附加扣除用于预扣，全年总额用于汇算，未就业月份等会使两者不同，需按实际资格核实，不能无条件乘 12。
- 同一项文字信息使用 comparisonGroups / bundles 对应的主键维护。旧字段原位保留，界面合并读取；用户保存合并文本后仅清空对应旧 value，保留证据元信息。AI 更新先阅读合并内容，避免再次向旧字段重复写入。
- 旧奖金、签字费、补贴说明在收入编辑中保留，参保地约定在缴费编辑中维护；新增条件写在所属项目。涉及试用薪资的数值只进入测算条件，合同格描述转正与合同约定。
- 自定义项只用于确实会影响选择、且现有项目无法容纳的差异。无需逐项打分或填满所有文字格；不得用完成率替代个人判断。
- 图表按现有计算结果绘制；条件不足显示税前已录小计，税后不绘制伪零值。年度比较使用同一发放年份；首年窗口单独说明。保留负净现金、未知金额和试算状态。

- 所有金额展示与数值输入统一为 k（千元），展示最多保留一位小数，例如 22k、35.5k。内部金额仍以元存储计算，读写表单时转换，保留分精度；缴费比例、月数、年份及工资系数保持原单位。
