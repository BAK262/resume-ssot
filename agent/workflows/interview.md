# interview：把简历问穿

> 路由 → [ROUTER.md](../ROUTER.md)。事实优先 `ssot.json` + 当前投递版。加强定位/开场/要点 → [resume.md](resume.md) Mode · pitch 与 [rules/resume.md](../rules/resume.md)。改 HTML → [resume.md](resume.md) / [patch.md](patch.md)。记面试进度 → [offer.md](offer.md)。

用户说「预测面试题 / 模拟面试 / 追问 / 把简历问穿 / 掌握度复盘 / 面试复盘落盘 / 一面结束」或 `/interview` 时走本流程。对用户称：**面试准备**（落盘后可称**面试复盘** / **暴露台账**）。

**不**替用户编一套可背答案；把重要 Claim 变成可验证问题，查是否真懂自己写过的职责、指标与结果。

```text
简历 / JD / 经历档案
  → 提取 Claim → 预测问题 → 问题树
  → 逐轮追问 → 知识缺口与事实风险 → 掌握度复盘
  →（实战面试后）岗复盘落盘 + 暴露台账
```

---

## 输入与边界

优先用对话内已有材料，少让用户重贴：

1. 投递版 / 通用版简历，或 `ssot.json` 对应经历  
2. 目标岗位与 JD  
3. 项目文档、代码、论文、公开链接  
4. 已确认职责、指标、结果  
5. 实战面试口述（Mode · debrief）

无 JD 可只按简历预测；无简历则先要简历或一段项目。材料不足标「待确认」，不补写未提供的经历/数据/技术细节。

问题优先验证简历真实主张，不堆无关八股。

**落盘边界**：

| 可写 | 不可写 |
|------|--------|
| 求职工作区：岗目录 `interview-rN-*.md`、`offers/interview-exposure-ledger.md` | `ssot.json`（经历档案） |
| 进度表 `note` 挂复盘/台账路径 | skill 包模板填入用户真实面试内容 |
| 对话内掌握度复盘（Mode · review） | 把掌握度评分当经历事实回写 |

默认：对话内 review **不**自动落盘。用户说「整理复盘文档 / 落盘 / 记入台账」或「一面结束」且随后要复盘文档 → Mode · debrief。

---

## Mode · predict（预测）

信号：「预测面试题」「会被问什么」/ `/interview predict`

1. 从经历/项目/技能/结果描述抽 Claim  
2. 结合目标岗排相关度、风险、优先级  
3. 分组：高概率 / 补充 / 压力  
4. 每题标明：来源、考察意图、回答应覆盖事实、可能下一层追问  

优先覆盖：个人边界强词；方案如何工作；指标 baseline/口径；关键决策与 trade-off；失败与复盘。

简洁结构示例：

```text
Q：……
来源：……
考察：……
回答应覆盖：……
追问：……
```

---

## Mode · grill（逐轮追问）

信号：「模拟面试」「追问我」「问穿」/ `/interview grill`

1. 选一高风险或高相关 Claim  
2. 建 Question Tree，**每轮只问一个**最值得答的问题  
3. 用户答后评估再决定是否下钻；分支够证据再换 Claim  
4. 用户暂停/要提示/结束 → 保留进度，出阶段性小结  

Claim 追问方向：背景 · 职责 · 结构 · 实现 · 决策 · 替代 · 失败 · 指标 · 代价 · 复盘。

优先追：模糊动词无动作；报数说不清 baseline；强表述划不清个人边界；只会 happy path；只会名词定义；只会结果不会实现；与简历/前文矛盾。

不要一次甩整棵树；卡住可给小提示或「先职责再实现」框架。**禁止**在用户未尝试前给可冒充成稿的标准答案。

---

## Mode · review（掌握度复盘）

信号：「总结一下」/ `/interview review` / 结束 grill / 口述实战面试后要分析（尚未要求落盘）

输出 Resume Mastery Review（默认只在对话）：

- 已验证较好的项目/技术/Claim  
- 高风险 Claim + 触发风险的回答  
- 再追两层易暴露的问题  
- 待补事实/待学技术点  
- 建议降强度、改写或暂缓的简历表述  
- 面试前优先 QA 清单  

用「高/中/低」或「已验证/部分验证/未验证」；样本不足写清范围，不用假精确总分。

发现「写得比掌握强」时给三选一：补事实 / 补学习 / 降低简历表述 → 可转 [resume.md](resume.md) Mode · pitch / [patch.md](patch.md)。

用户接着要「整理复盘文档 / 暴露台账」→ Mode · debrief（review 的建议**不**写入岗复盘文件）。

---

## Mode · debrief（实战复盘落盘）

信号：「面试复盘」「整理复盘文档」「一面/二面结束」+ 要落盘；「更新暴露台账」/ `/interview debrief`

对用户称：**面试复盘**（单岗）· **暴露台账**（跨岗总表）。

### 两份磁盘产物

| 产物 | 路径 | 内容 |
|------|------|------|
| 岗复盘 | 该岗投递版目录 `interview-rN-YYYYMMDD.md`（N=轮次） | **仅**流程、问答、编程题、面试官当场反馈、候选人当场自我判断 |
| 暴露台账 | `offers/interview-exposure-ledger.md`（无则从模板复制） | 跨岗：暴露点 → 补齐方向；来源链到岗复盘 |

骨架：`templates/interview-debrief.example.md`、`templates/interview-exposure-ledger.md`。

### 岗复盘写法

1. 从表头对齐进度表条目（公司/岗位/日期/形式/进度 id/投递版路径/结果状态）。  
2. 按面试实际分段：自我介绍 → 项目追问 → 代码/业务题 → 收尾反馈。  
3. **禁止**写入 Agent 的掌握度评分、优先 QA 清单、话术建议、「你应该…」类总结（那些留在对话 Mode · review）。  
4. 面试官原意尽量保留；候选人答不清处如实记「当场未完全领会」等自述，不代填标准答案。

### 暴露台账写法

1. 从本场问答抽出：卡顿 / 被追问住 / 面试官明示短板。  
2. 每条：`暴露点` + `补齐方向`（可执行：要补的事实/技术/肌肉记忆）+ `来源`（公司·岗位·轮次·复盘相对路径）+ `状态`（开放/已关闭）。  
3. 主题相同则合并一行，来源列追加岗位。  
4. 「按岗位索引」表追加本场。  
5. 补齐完成：行移入「已关闭」，注完成日期与证据。

### 与进度表

同步 [offer.md](offer.md)：状态按证据更新（无过关证据不升轮次）；`note` 挂岗复盘与台账路径；写当前 ISO `updatedAt`。短报提醒刷新进度表。

### 默认交付

岗复盘路径 · 台账路径（或「已合并 N 条」）· 进度表已挂链 · 刷新可见。

## Claim 类型（提取时优先）

| 类型 | 追到 |
|------|------|
| Ownership | 范围、亲自实现、关键决策、他人职责 |
| Metric | baseline、分母、周期、来源、个人 vs 团队 |
| Technical | 项目中作用、I/O、负责部分、选型与 trade-off |
| Architecture | 组件、数据流、边界、故障、扩展限制 |
| Result | 是否交付、谁用、如何衡量、个人动作 |

---

## 回答评估维度

正确性 · 具体性 · 个人边界 · 深度 · 证据 · 与简历/前文一致性。只评当前证据，不脑补。

## 与其他流程

| 需要 | 转 |
|------|----|
| 加强定位/开场/要点 | [resume.md](resume.md) Mode · pitch + [rules/resume.md](../rules/resume.md) |
| 改 HTML/PDF 表述 | [resume.md](resume.md) / [patch.md](patch.md) |

推荐顺序：经历档案稳 → 投递版（含证据化改写）→ predict/grill/review → 实战 → **debrief 落盘** → 进度表更新。
